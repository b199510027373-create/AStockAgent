# ADR-009 LLM 只解释，不参与排序

- 状态：accepted
- 日期：2026-11-03
- 来源：产品文档 v1.0 架构输入；评审 §5「不建议现在做」

## 背景

DeepSeek 接入后，最诱人的做法是让模型"综合判断"给出买卖建议。但这会让整个可复现体系崩塌：

- 同一批数据、同一参数，两次调用可能给出不同排序；
- 模型幻觉会进入回测与跟踪，污染统计结论；
- 无法解释"为什么这个分数是 90.7"。

## 决策

1. LLM 只写「逻辑 / 催化 / 风险」三类文本，输入限定为已检索到的证据。
2. LLM **不得修改** `action`、`confidence`、综合分或排序；排序完全由技术分 + 事件分决定。
3. 没有 API key 或调用失败时，自动退回规则理由，流程不中断。
4. 输出要求严格 JSON；解析失败按失败处理，不猜测。
5. 证据不足时明确输出"资料不足"，禁止编造。

## 后果

- 正面：排序可复现、可回测；LLM 成本与风险可控；离线可跑。
- 负面：解释价值受证据质量限制；"AI 选股"的叙事弱化（这是有意为之）。
- 约束：若未来要让 LLM 参与排序，必须先有可复现的提示版本、缓存与离线评估集，属于重新立项。

## 证据

- `astock/recommend.py`（`_llm_rank` 只做文案）
- `astock/llm.py`（直连/代理切换、失败兜底）
- `docs/AStockAgent_architecture_v1.3.md` §1 原则
