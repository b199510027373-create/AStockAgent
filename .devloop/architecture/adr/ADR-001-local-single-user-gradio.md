# ADR-001 本地单用户 Gradio 研究台

- 状态：accepted
- 日期：2026-11-03
- 来源：2026-10-26 构建会话（会话 52a72bc0）、2026-11-02 评审会话（会话 74b9abee）、评审 §5

## 背景

AStockAgent 是单人本地使用的 A 股研究工具：入口是 Gradio 13 个 Tab，运行在 `127.0.0.1:7861`。使用场景是"每天收盘后看一眼推荐、做点因子/回测实验"，没有多用户、远程访问、权限隔离的真实需求。

历史问题是 `app.py` 曾把指标、组合、回测、推荐逻辑都写在 UI 文件里，导致"改一个点，六个 Tab 口径不一致"。评审明确指出：**不要拆微服务、不要上 FastAPI、不要做多用户**，在单用户场景下没有收益，只会让 13 个 Tab 的调试成本翻倍。

## 决策

1. 交付形态保持**本地单用户 Gradio**，不引入 FastAPI、任务队列、微服务或鉴权体系。
2. 交互层只做装配：`app.py` 负责 Tab 组装与事件绑定，业务逻辑必须下沉到 `astock/` 领域/用例模块。
3. 进程边界只有两个：Web 应用进程与独立调度进程（见 ADR-004）。
4. 对外暴露只允许 loopback；不做公网部署方案。

## 后果

- 正面：零前端成本、迭代快、离线可跑；13 个 Tab 的调试链路短。
- 负面：无并发隔离、无鉴权、不可远程共享；Gradio 版本升级可能破坏布局。
- 约束：任何"多人使用/远程访问"需求出现时，属于重新立项，不在现有架构上打补丁。
