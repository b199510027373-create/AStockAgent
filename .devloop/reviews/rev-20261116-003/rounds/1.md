## 本轮问题

### P1 · 分布/指标/桥接产物缓存键漏掉 start/end，换窗口不加 --refresh 会静默复用旧窗口产物

- 位置：`astock/sw_crosswalk.py:688-694,702-704,709-713`
- 状态：未闭环
- 置信度：0.9

**证据**

产物路径只含 index_code：:688-689 `dist_path = PIT_DIR / f"sw_crosswalk_distribution_{index_code}.parquet"`、`metrics_path = ... f"sw_crosswalk_metrics_{index_code}.parquet"`，:704 桥接 JSON 用 `BRIDGE_FILE_TEMPLATE.format(index=index_code)`（模板为 "sw_crosswalk_bridge_{index}.json"），三者都不含 start/end；:690-694 只要两个 parquet 非空就直接 `return cached_dist, cached_metrics`，:702 的 bridge 也只在重建分支里写。而 CLI :711-713 明确开放 `--start` / `--end`。因此执行 `python -m astock.sw_crosswalk --start 2021-12-01 --end 2022-01-31`（不加 --refresh）时，命令会打印「distribution rows: 13」并返回 2021-06-01..2022-05-31 的旧产物，用户无法从输出察觉窗口被忽略；只有加 --refresh 才会真正换窗口，而桥接 json 还会被用新窗口覆盖旧窗口的 000300.SH 文件。对照 ADR-011「基础口径变化即失效」，这里窗口变化正是口径变化。现有 tests/test_sw_crosswalk.py 的缓存用例（:324-344）只覆盖了 crosswalk edges 的缓存命中，没有任何用例覆盖分布产物缓存与换窗口重建。

**建议**

让缓存键与窗口绑定：①把产物名改为含窗口的形式（如 sw_crosswalk_metrics_{index}_{start}_{end}.parquet，与 pit.py:256 的 snapshot_v2_{index}_{start}_{end} 一致），或②在目录里写一个 meta（index/start/end/bridge_old_date/bridge_new_date/thresholds/edges 的 mtime 或 sha），命中前逐项比对，任一不符即重建，并在 rebuild 时删除过期 bridge json。同时补两条 pytest：先用窗口 A 生成产物，再用窗口 B 且 refresh=False 调用，断言返回的是重建后的行数而不是旧行数。

### P1 · 结构性阈值/桥接日无法从流水线传入，且缓存命中不校验，doc §2 的「改切点重跑」不成立

- 位置：`astock/sw_crosswalk.py:311-330,335,343-348,709-714`
- 状态：未闭环
- 置信度：0.9

**证据**

`build_crosswalk_artifacts` 签名（:311-318）只有 refresh/old_members/new_members/old_date/new_date，没有 old_share/new_share；:335 直接 `edges = edge_table(pairs)` 使用模块常量 STRUCTURAL_OLD_SHARE=0.20 / STRUCTURAL_NEW_SHARE=0.50，所以阈值只能绕过整条流水线、手写脚本调 edge_table(pairs, old_share=..., new_share=...) 才能改。缓存侧：:322-330 命中条件只有「edges parquet 非空 + summary.json 可解析」，从不比对 summary 里已写好的 `thresholds`（:345-348）与 `bridge_old_date`/`bridge_new_date`（:343-344），也不比对输入 sw_l1_members parquet 的 mtime。后果一：改了常量后重跑（不加 --refresh）返回旧 edges 与旧 summary，summary 里的 thresholds 会与代码常量不一致而无人察觉；后果二：传 old_date="2021-12-01" 之类的新桥接日，缓存命中时该参数被完全忽略。这与 docs/sw2014_sw2021_crosswalk.md:27「阈值是显式参数，便于复核时改切点重跑」以及验收标准①「可审计映射表」直接冲突——审计者按文档改切点重跑，拿到的还是旧表。

**建议**

把阈值做成真正的参数：给 build_crosswalk_artifacts 增加 old_share/new_share 形参并透传到 edge_table，CLI 增加 --old-share/--new-share（默认 0.20/0.50）；缓存命中前比对 cached_summary["thresholds"]、bridge_old_date/bridge_new_date 与目标输入（含 sw_l1_members parquet mtime），不一致就重建。补两条 pytest：①阈值改成 0.10/0.40 且 refresh=False 时必须重建并得到更多结构性边；②桥接日改成 2021-12-01 时必须重建、summary 的 bridge_old_date 随之变化。

### P2 · distribution parquet 未标记非 SW 回退标签且权重分母口径与 metrics 不同，与 doc:88 表述冲突

- 状态：未闭环

**证据**

distribution_table（astock/sw_crosswalk.py:362-382）直接 `frame.groupby(["date","industry"])`，不过滤非 SW 回退标签，weight_share 分母是当日全部行权重（:379-380）；而 snapshot_metrics（:398-474）只统计落在版本全集内的真实 SW L1、把 fallback 单列、权重分母用 SW 子集。两个 parquet 都在 doc:146-147 作为产物列出，于是同一 date+industry 在两个文件里 weight_share 含义不同（例如 2021-06-30 食品饮料在 distribution parquet 里按 300 只分母、在 metrics 里按 292 只分母）。更关键的是 distribution parquet 只带 industry_version 列（:373），而 pit.py:286/301 给回退行打的 industry_version 同样是 SW2014/SW2021，所以使用方无法从该文件区分「半导体/医疗保健/软件服务/运输设备/通信设备/电气设备」这些 stock_basic 回退名与真实 SW 行业——这与 doc:88「分布统计已只使用真实 SW L1，非 SW 行单独列示，避免污染行业数与 HHI」的表述不一致，§5.2:123 又要求做行业中性化时必须剔除或单独标记。
