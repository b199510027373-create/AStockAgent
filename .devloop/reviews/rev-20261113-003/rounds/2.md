### P1 · JSON Schema 的 data.ref 使用 oneOf，合法指数代码会同时命中 stock/index 两个分支而被拒绝

- 位置：`astock/agent/chart_spec.py:949-956`
- 状态：未闭环
- 置信度：0.96

**证据**

STOCK_REF_RE=^[0-9]{6}\.(SH|SZ|BJ)$（:123）匹配所有六位代码，INDEX_REF_RE=^000[0-9]{3}\.SH$|^399[0-9]{3}\.SZ$（:124）是它的子集；因此合法指数代码如 000001.SH、399001.SZ 会同时匹配两个 pattern。JSON Schema 的 oneOf 要求恰好命中一个分支（:949-956），实际会拒绝这些合法 ref；而运行时校验在 :480 用 `STOCK_REF_RE or INDEX_REF_RE`，会接受。现有测试 tests/test_agent_chart_spec.py:405-409 只验证运行时接受指数，:572-583 只检查 oneOf 有三个 pattern，没有真正用 jsonschema 校验指数 ref，所以没暴露该冲突。

**建议**

把 data.ref 的 oneOf 改为 anyOf（或从 STOCK_REF_RE 排除 000xxx.SH / 399xxx.SZ 指数前缀，保留互斥），并在 tests/test_agent_chart_spec.py 增加真正的 jsonschema.validate 用例：000001.SH、399001.SZ 必须通过，art_ 与非法代码按预期失败。确保 schema 与 validate_chart_spec 的接受集合一致。

- 状态：未闭环
- 置信度：0.9

**证据**

apply_transforms 末尾把 frame.attrs 原样复制到 transformed（chart_render.py:317-320）；_load_artifact_frame 会把旧 meta 的 data_as_of/data_time 写入 attrs（:254-257）。render 在 transforms 之后调用 _time_points（:1125-1136），而 _time_points 在 frame.empty 时跳过时间列探测，随后 `snapshot_as_of = frame.attrs.get("data_as_of")`（:543-546）仍返回旧时点并写进图注/artifact。现有 tests/test_agent_chart_render.py 没有“artifact 源 + filter 过滤掉全部行”的用例，因此空态仍显示原数据截止日而非“时点未知”。
