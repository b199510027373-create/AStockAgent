### P1 · 75b5d64 将 data.ref oneOf 标记 fixed，但 schema 仍用重叠 pattern 的 oneOf，jsonschema 仍拒绝合法指数代码

- 位置：`astock/agent/chart_spec.py:947-956`
- 状态：未闭环
- 置信度：0.97

**证据**

`devloop_review get` 把 `iss-mwf84sjv-42aad0` 标成 status=fixed，但 75b5d64 没有改 `_JSON_SCHEMA.data.ref`：:949-956 仍是 `oneOf: [{"pattern": STOCK_REF_RE}, {"pattern": INDEX_REF_RE}, {"pattern": ARTIFACT_REF_RE}]`。`STOCK_REF_RE = ^[0-9]{6}\.(SH|SZ|BJ)$` 覆盖所有六位代码，`INDEX_REF_RE = ^000[0-9]{3}\.SH$|^399[0-9]{3}\.SZ$` 是它的真子集；因此 `000001.SH`、`399001.SZ` 同时匹配 stock 与 index 两个 branch，而 JSON Schema 的 `oneOf` 要求恰好一个 branch 匹配，合法指数 ref 会被 schema 判为 invalid。运行时 `validate_chart_spec` 用 or 判断（chart_spec.py:488-495）会接受，所以模型拿到 schema 后会被误导，与“schema 即字段与枚举白名单”不一致。tests/test_agent_chart_spec.py:575-577 只断言 `len(oneOf)==3` 和 pattern 文本，没有用 jsonschema 实际校验 `000001.SH`/`399001.SZ`，所以这个 false fixed 没被发现。

**建议**

`record_artifact` 用 `artifact_id_for(digest, filename)` 生成 id，然后 `INSERT ... ON CONFLICT(artifact_id) DO NOTHING`（store.py:253-263），不比较也不更新已有行的 meta。`chart_render.render` 的 artifact_id 只由 HTML digest 派生（chart_render.py:1219-1224），PNG 是否成功、`degraded` 与 warnings 都不改变 HTML 字节：PNG 在 `:1228-1239` 单独 `put_content`，meta 在 `:1253-1275` 才写。于是同一 spec/数据第一次在无 kaleido 环境渲染（`degraded=True`、`png_path=None`），第二次在装了 kaleido 的环境渲染（`degraded=False`、`png_path=/...png`）会复用同一 HTML digest/artifact_id，第二次 `record_artifact` 直接 DO NOTHING，DB 里的 `meta_json` 仍是第一次的 `degraded=True`/`png_path=None`；反过来先成功后失败也会保留旧 png_path。`RenderedFigure` 返回值与 DB 记录不一致，artifact 回放/审计会看到错误的降级状态。现有测试没有覆盖同 digest 不同 PNG/degraded 的二次渲染。

### P2 · prune_artifacts 只清理已记录 digest，PNG 独立 digest 目录在 HTML artifact 删除后成为孤儿
