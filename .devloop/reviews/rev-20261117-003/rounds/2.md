## 本轮问题

### P1 · artifact 身份未包含 include_plotlyjs，同一 spec/data/env 切换内联/CDN 会撞身份并硬失败

- 位置：`astock/agent/chart_render.py:1368, 1443-1461`
- 状态：未闭环
- 置信度：0.9

**证据**

render 的 include_plotlyjs 是独立参数（chart_render.py:1368），直接决定 figure.to_html 的输出（1443-1448）；但 artifact_id 只用 data_digest+env_fingerprint+canonical_json(normalized)（1457-1461），normalized 来自 validate_chart_spec(spec)（1389），不包含这个独立参数（astock/agent/chart_spec.py 中无 include_plotlyjs）。因此同一 spec/同一份数据/同一环境先以 include_plotlyjs="inline" 渲染、再以 "cdn" 渲染，会得到同一个 artifact_id，但 HTML 字节不同；store.record_artifact 发现已存在行的 content_digest 不同会抛 ArtifactIdentityConflict（store.py:790-799）。这是正常 API 用法（测试 tests/test_agent_chart_render.py:111 默认 cdn、132 用 inline），却会硬失败。现有回归只测了 code_version 变化（env 变）和文件名变化，没有测同一 spec 的 include_plotlyjs 变化。

**建议**

把会影响 HTML 字节的渲染选项纳入身份：在 canonical_spec 中加入 render_options.include_plotlyjs（以及未来任何输出影响参数），或把 HTML content_digest 一并纳入 artifact_id 种子；record_artifact 的 content_digest 校验应只用于同一身份的内容一致性。补回归测试：同一 spec/data/env 下 include_plotlyjs="inline" 与 "cdn" 各渲染一次，断言生成两个 artifact（或明确后者复用前者的策略），且不抛 ArtifactIdentityConflict；再断言两次的 HTML 均可读。

### P1 · GC 的 protected 集合漏掉 data_blob，90 天后会删掉仍被 artifact 引用的数据快照

- 位置：`astock/agent/store.py:1204-1220, 1270-1287`
- 状态：未闭环
- 置信度：0.92

**证据**

chart_render 现在把快照写到独立 blob，并把相对路径放进 meta["data_blob"]（chart_render.py:1572-1577，record_artifact 在 1579 起写入版本）。但 _protected_paths 只收集 agent_artifacts.path 和版本 meta 的 png_rel_path/png_path（store.py:1204-1220），没有 data_blob；prune_artifacts 用这个集合跳过受保护文件（store.py:1270-1280），prune_orphan_blobs 也复用同一集合（store.py:1307 起）。因此 data.json 在 mtime 超过 90 天后会被当作无引用 blob 删除，而 artifact/version 行仍在；之后 load_artifact(mode="recomputed")/回放会因 blob 缺失失败。现有 GC 测试只覆盖 png/path（tests/test_agent_store.py:598-624、627-646），新增的 snapshot 测试只断言 blob 存在（tests/test_agent_chart_render.py 的 meta/blob 用例），没有跑 prune 后回放。

**建议**

在 _protected_paths 的 meta 遍历中加入 data_blob（同样做相对路径规范化与 is_relative_to 校验），并让 prune_artifacts/prune_orphan_blobs 都使用它；补回归测试：真实 render 生成 data.json 后，把 mtime 改到 90 天前，调用 prune_artifacts/prune_orphan_blobs，断言 data.json 仍在且 load_artifact(recomputed) 仍可回放；同时断言无引用的 blob 仍会被删。另建议把 data_blob 与 png_rel_path 的键名统一成白名单常量，避免以后新增 blob 再漏。

### P2 · 内存库 v1 迁移仍把 DEFAULT_DB_PATH 当备份目标（P2-G 仅部分修复）
