### P2 · 每个流式分片都重算引用卡片并同步读盘（glob 全部 meta.json + 整读正文），回答越长越卡

- 位置：`astock/agent_chat_ui.py:184-185`
- 状态：未闭环
- 置信度：0.85

**证据**

respond() 的每一帧（含每个 40 字 answer 分片）都无条件调用 render_citations_html(citations)（astock/agent_chat_ui.py:184-185），而 render_citations_html 对每条引用同步调用 resolve_citation（astock/agent/chat.py:551-552）；resolve_citation 每次 load_meta + list(iter_chunks) 整读 extracted 内容（astock/agent/chat.py:501-504），answer 文本里的引用 file_id 为 None（astock/agent/chat.py:461-464），于是还要 _find_file 去 glob data/agent/files/*/meta.json 并逐个 read_text+json.loads（astock/agent/chat.py:468-479）。一次 3000 字回答约 75 帧 × 最多 20 条引用 × 全量 meta 扫描，全部发生在 Gradio 生成器里，流式观感会被同步磁盘 I/O 拖慢；且这些重算对同一批 citation 的结果完全不变。当前测试也没有对每帧重算行为的约束。

**建议**

在 respond() 里缓存上一次的 citations 指纹（如 tuple((c.label, c.page, c.sheet, c.file_id) for c in citations)）与对应 HTML，只在 step/done 帧或指纹变化时重算 answer 帧直接复用；同时给 render_citations_html 增加可选的 memo 字典参数，把 resolve_citation 结果按 (label, page, sheet) 缓存。改完后在 tests/test_agent_chat.py 补一条断言：连续两个相同 citations 的 answer 帧只发生一次 resolve（可用 monkeypatch 计数）。

### P2 · 中断在「新闻检索/建模型」阶段完全失效且提示误导，本地 cancel Event 是死参数

- 位置：`astock/agent/chat.py:676-683`
- 状态：未闭环
- 置信度：0.82

**证据**

interrupt() 只在 runtime 已创建且 self._busy.locked() 时才调 runtime.request_interrupt()，否则返回「当前没有正在生成的回答。」（astock/agent/chat.py:676-683）。而 ask() 在 _ensure_runtime() 之前先同步执行 context_provider（astock/agent/chat.py:707-709），app.py:480 注入的 _chat_page_context 会走 build_ai_context 的新闻/公告检索，可能耗时数秒；这段时间 _busy 已 locked 但 runtime 仍为 None，用户点「⏹ 中断」得到的是「当前没有正在生成的回答」，紧接着 chat.py:729 的 self._cancelled.clear() 又把它抹掉，run 照常完整执行并显示「✅ 已完成」——中断请求被静默丢弃。另外 chat.py:728 的局部 cancel = threading.Event() 交给 runtime.run(cancel_event=cancel)，但没有任何代码路径 set 它（interrupt() 只设 _cancelled 和 self._interrupt），是死参数，容易让后续维护者误以为两条取消通道都在工作。

**建议**

把判定改成「self._busy.locked() 即视为已请求中断」并返回「⏹ 已请求中断…」，runtime 为 None 时也能生效；在 _ensure_runtime() 之后、启动 worker 之前检查 self._cancelled，若已置位就直接 yield done(_STOP_LABELS["interrupted"]) 并 return（finally 释放锁），不再启动 run。同时把 chat.py:728 的局部 cancel Event 挂到实例（如 self._cancel_event）并在 interrupt() 中 set 它，或直接删掉该形参，保持单一取消通道。
