## 本轮问题

### P0 · 日/周/月线连续指标全部为空（MA/BOLL/MACD/RSI/KDJ 静默丢失）

- 位置：`astock/agent/chart_render.py:1579, 945, 1080`
- 状态：未闭环
- 置信度：0.97

**证据**

render_figure 在 1579 行无条件执行 `indicator_frame = market.continuous_bars(transformed, freq=freq) if view_column else None`。日/周/月线的 `_period_freq` 返回 D/W/M（chart_render.py:849-850、95），`data.classify_bar_time` 对非分钟频率直接返回 "close"（data.py:923-925），而 `continuous_bars` 只保留 session=="continuous"（data.py:951-956）——因此日/周/月线的 indicator_frame 恒为空表。`_indicator_frame` 以 `base=source_frame` 计算 `sma(close).reindex(frame.index)`（chart_render.py:599、619），`_pane_series` 同样以空表计算后 reindex（634-655），结果 MA/BOLL/MACD/RSI/KDJ 全部为 NaN；`_build_figure` 仍无条件 add_trace（992-1006、1079-1080），所以图例里有名字、图上没有线，且没有任何 warning。现有测试 `test_candlestick_supports_ma_boll_and_volume`（412-422）和 `test_candlestick_indicator_panes`（425-429）只断言 HTML 中出现图例文字，NaN 也能通过。该问题影响最常用的日线 K 线叠加指标路径，属于本分支 Q7 过滤引入的静默正确性回归。

**建议**

1) 只对分钟周期做连续竞价过滤：`indicator_frame = market.continuous_bars(transformed, freq=freq) if freq in MINUTE_FREQS else transformed`（日/周/月线全部是 close bar，应全部参与指标计算）；或让 `continuous_bars` 对非分钟频率返回全部行并同步调整 Q7 测试。2) 在 `_indicator_frame`/`_pane_series` 增加防御：当请求了 layers 但 indicator_frame 为空时写 warning，避免再次静默。3) 补数值断言而不只是图例名：对 daily/weekly/monthly 的 `layers=[{"type":"ma","window":20}]`，用 `indicators.sma(close,20)` 算出期望序列，断言渲染结果中 MA20 trace 的 y 与期望一致（至少尾部非 NaN）；保留现有 auction-only 分钟用例验证集合竞价被排除。修复后重跑 `pytest tests/test_agent_chart_render.py -q`。

### P1 · 传入不存在的 run_id 时 chart_service 自建 running run 且成功后永不 finish

- 位置：`astock/agent/chart_service.py:114-125, 140-144`
- 状态：未闭环
- 置信度：0.94

**证据**

chart_service.py:113 注释写「只有调用方明确给了真实 run 才登记；直接渲染绝不合成 run」，但 114-125 行在 `run_id is not None` 且库中查不到时直接 `ensure_run(..., status="running", session_id=session_id or "chart")`；随后只有 `PNGExportError` 分支会 `fail_run`（140-144），正常成功或其它异常路径都没有 finish。store.py:447 的 `ensure_run` 文档明确「v2 起 agent_runs 只服务真实 Agent（run_kind='agent'）；直接渲染不调用本函数」，v2 冻结 §5 要求 ensure_run/finish_run 成对。结果是任何调用方传入一个尚未创建的 `run_id`，都会在审计库留下永久 `status='running'` 的 run；测试 `test_png_mode_require_raises_and_marks_run_failed`（tests/test_agent_chart_render.py:581-602）恰好把这个自动建 run 的行为固化成期望，掩盖了成功路径的泄漏。

**建议**

chart_service 不应创建 run：若 `run_id` 非空但库中不存在，直接抛 `ValueError`/`ChartSpecError`（文案说明「run_id 必须由 runtime 先 ensure_run」），让 run 生命周期只归 runtime；成功渲染不得修改 run 状态。若确实要保留自动建 run 的兼容行为，则必须在 finally 中 finish，但这会把 Agent 的 run 提前结束，故推荐 fail-fast。同步修改 tests/test_agent_chart_render.py:581-602：改为预建 run 后测试 PNG 失败置 failed，并新增「传入不存在的 run_id 抛错且不新增 agent_runs 行」「成功后既有 run 仍为 running、由 runtime finish」两个用例。

### P1 · Agent 出图未关联真实 run，全部落成 source="render"、run_id=NULL

- 位置：`astock/agent/tools/market_tools.py:1073-1082`
- 状态：未闭环
- 置信度：0.95

**证据**

`_render_chart_payload` 调用 renderer 时传了 spec/frame/db_path/artifact_root/data_as_of/data_time/export_png/session_id，但没有传 `run_id`/`step`（market_tools.py:1073-1082）。AgentRuntime 在 `_start_audit` 生成 `run_<uuid16>` 并 `ensure_run(... status="running")`（runtime.py:555-581），工具执行走 `self.registry.invoke(call.name, prepared)`（runtime.py:495），整条链路没有把 run_id 传给工具。chart_service.render_chart 因此在 145-147 行落到 `source="render"`、`reason="render"`、`actor="system"`，artifact link 的 run_id 为 NULL。规格 §7.1 明确「Agent 调用必须 record_artifact(run_id=run_id, step=step, source="agent")」；v2 冻结 §5 也要求真实 run 与 artifact link 成对。现有 `test_agent_render_links_real_run...`（tests/test_agent_chart_render.py:1209-1231）先手工 `ensure_run` 再直接调 render，绕过了 runtime/tool，故 CI 全绿但线上 Agent 出图没有 run 关联，审计无法回答「这张图属于哪次对话/哪一步」。`source="render"` 还会让直接渲染与 Agent 渲染在审计上不可区分。

**建议**

在 runtime 与工具之间建立显式上下文：AgentRuntime 在 dispatch 前把当前 `run_id` 与 step 序号写入 `ToolContext`/`ContextVar`（或扩展 `registry.invoke` 签名），`_render_chart_payload` 从中取 `run_id`/`step` 并传给 `render_chart`；直接 UI 渲染不设置上下文，仍走 `source="render"`。补一个端到端测试：通过 AgentRuntime + 默认 registry 触发 chart 工具，断言 `agent_run_artifacts` 的 link 为 `(真实 run_id, "agent", step)`，且该 run 最终 status 由 runtime finish；另保留「无 run 的直接渲染 link.run_id 为 NULL」用例。

### P2 · 图注把所有“视图时点未知”都归因为“聚合后无时间列”

- 位置：`astock/agent/chart_render.py:704-705, 1550-1551`
- 状态：未闭环
- 置信度：0.86

**证据**

`_caption` 在行情时点存在、视图时点为空时无条件拼接「视图时点未知（聚合后无时间列）」（chart_render.py:704-705）。但视图为空不止「聚合掉时间列」一种原因：`render_figure` 在 1533-1534 行对 `time_semantics=none` 明确走「行情时点未知（不编造 data_as_of）」的另一条语义；带 recorded data_as_of 的 artifact 快照 + `time_semantics=none` 且 transforms 为空时，market 有值、view 为空，图注仍会说「聚合后无时间列」，与实际原因不符。`render_figure` 1550-1551 行只在 `normalized["transforms"]` 非空时才写聚合 warning，说明代码本身已区分原因，但 `_caption` 没有拿到这个区分。§3.2 的五档图注要求原因准确，当前会对「声明 none / 无 transforms」的图给出误导性归因。

### P2 · load_chart_artifact 重算 meta_digest，无法校验记录 meta 是否被篡改

- 位置：`astock/agent/chart_service.py:339-340`
- 状态：未闭环
- 置信度：0.92

**证据**

chart_service.load_chart_artifact 在 339-340 行把 `payload["meta_digest"]` 设为 `meta_digest(meta)`，而 `meta = dict(record.meta)` 正是从同一条 version 记录读出的 meta_json；重算值必然与同一输入自洽，无法证明库内 `agent_artifact_versions.meta_digest` 未被篡改。store.ArtifactRecord（612-622）没有 meta_digest 字段，`_row_to_record`（886-897）也没把 `version_row["meta_digest"]` 带出来（record_artifact 在 819-826 行确实写入了该列）。v2 冻结 §7 写明「真实性以 content_digest + meta_digest 为准」；当前 as_recorded 只通过 load_artifact 校验了 HTML 的 content_digest，meta 的完整性没有校验。

**建议**

给 `ArtifactRecord` 增加 `meta_digest: str` 字段，在 `_row_to_record` 中传 `version_row["meta_digest"]`；`load_chart_artifact` 改用 `record.meta_digest`，并断言 `meta_digest(record.meta) == record.meta_digest`，不一致抛 `ArtifactReplayUnavailable`（或至少追加高优先级 warning 并在 payload 标 `meta_verified=False`），不要静默用重算值。补一个测试：直接改库内 meta_json 后重新 `load_chart_artifact(..., mode="as_recorded")`，应检测到 meta_digest 不匹配；再补正常路径断言 payload.meta_digest 等于写入时的 digest。
