## 本轮问题

### P1 · 数值列强转 float 会把股票代码等前导零标识符改坏（000001 → 1.0），且无告警

- 位置：`astock/agent/files.py:911-920`
- 状态：未闭环
- 置信度：0.85

**证据**

`_coerce_column` 对 object 列执行 `numeric = pd.to_numeric(non_null, errors="coerce")`（616 行）后 `if numeric.notna().all(): return pd.to_numeric(series, errors="coerce").astype(float)`（617-619 行）。`_normalize_cell` 本来把 "000001" 保留成字符串，但这里整列被判定"可转数值"后写进 parquet 变成 [600000.0, 1.0]。tests/test_agent_files.py:329 的夹具已经包含 `000001`，但 350 行只断言了 `frame["收盘价"] == [12.5, 13.5]`，没有断言 `代码` 列，所以这个数据损坏没有被发现，也没有任何 warning。后果：extracted.jsonl/chunk 文本里是 "600000 | 12.5 | 1000"，而 `load_table`/后续 table_query 返回的代码是 1.0，A 股 6 位代码被静默篡改，用户和 Agent 都无法察觉。

**建议**

在 `_coerce_column` 里加标识符保护：只有当整列原始值都是真数值类型（`all(isinstance(v, (int, float)) and not isinstance(v, bool))`）时，或字符串值不含前导零（`re.match(r"^0\d", v)` 全 False）且不含逗号/单位时才转 float；命中前导零就整列 `return series`（保持字符串），并追加一条 `extraction_warning:` 说明该列按文本保留。同时在 tests/test_agent_files.py:350 后补断言 `frame["代码"].tolist() == ["600000", "000001"]`，用一个显式用例锁住"代码列不被转数值"。

### P1 · load_table 的 sheet_slug 未做白名单/归属校验，可路径穿越或绝对路径逃逸出 data/agent/files

- 位置：`astock/agent/files.py:1282-1287`
- 状态：未闭环
- 置信度：0.8

**证据**

`load_table` 直接用调用方传入的 `sheet_slug` 拼路径（1286 行）：`path = file_dir(file_id, root=root) / "tables" / f"{sheet_slug}.parquet"`，没有任何白名单/解析后归属校验。两个逃逸面：1) `sheet_slug="../../<另一个 sha256>/tables/sheet"` 可读到别的内容寻址目录里的 parquet；2) Windows 下 `sheet_slug` 若是绝对路径（如 `C:/Windows/...` 或 `/etc/...`），pathlib 的 `/` 运算符会丢弃左侧前缀，直接读到任意位置。`load_table` 在 `__all__` 里导出，plan-20261107-004 的 `table_query(file_id, sheet, sql)` 会把模型给的 sheet 参数喂进这条路，属于模型可控输入。现有测试只覆盖了 `file_dir("../../etc")`（tests/test_agent_files.py:684-694 走的是 meta.json 扫描分支，本身安全），`load_table` 的越权路径零覆盖。违反接口冻结清单 §4「仅允许 data/agent/files/ 下的读取，拒绝路径穿越与符号链接」与契约 AGENT-05。

**建议**

路径构造前先校验 slug：`if not re.fullmatch(r"[a-z0-9_]{1,48}", sheet_slug): raise ValueError("非法 sheet_slug")`（与 `_sheet_slug` 产出规则一致）；再把 `tables_dir = (directory / "tables").resolve()` 与 `path.resolve()` 做 `is_relative_to(tables_dir)` 断言，双保险覆盖 `..` 与绝对路径。同步补 `test_load_table_rejects_traversal`：分别断言 `"../../x"`、`"../meta"`、绝对路径三种输入抛 ValueError/FileNotFoundError，且不产生任何读取。

### P2 · 原子写临时文件名只用 pid，同进程并发导入同一 sha256 时会共用 tmp 路径

- 位置：`astock/agent/files.py:1173-1177`
- 状态：未闭环
- 置信度：0.7

**证据**

`_atomic_write_bytes`（astock/agent/files.py:1173-1177）用 `tmp = target.with_name(f".{target.name}.tmp-{os.getpid()}")` 生成临时文件，唯一性只依赖进程号。同一文件目录下的多个目标（original.<ext>、meta.json）各自有 tmp 名所以互不冲突，但同一 sha256 的两次并发 ingest（Gradio 默认线程池里两个上传请求，或一次批量里同一文件被传两次）会在同一进程里落到同一个 tmp 路径：两个线程同时 `tmp.write_bytes()`，`os.replace()` 时可能拿到另一个线程写了一半的内容，且 `_write_original` 里 `others = [p for p in directory.glob("original.*") if p != target]` 逻辑会因 tmp 后缀不同而漏判。ADR-011 与项目既有的原子写约定要求临时文件名唯一（uuid/随机后缀），失败后清理残留。

**建议**

tmp 名改为 `f".{target.name}.tmp-{os.getpid()}-{uuid.uuid4().hex[:8]}"`（或 `secrets.token_hex(4)`），并用 try/finally 在写入失败时 `tmp.unlink(missing_ok=True)`；补一个用例：monkeypatch 让 `Path.write_bytes` 抛 OSError，断言调用后目录里没有残留 `.tmp-*` 文件且 meta.json 不存在。
