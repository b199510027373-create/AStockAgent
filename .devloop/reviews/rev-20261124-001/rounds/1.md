### P2 · 空分组被序列化成字面量「None」，文本分类按字典序排序导致 x 轴顺序失真

- 位置：`astock/agent/tools/file_tools.py:606-608, 618-621`
- 状态：未闭环
- 置信度：0.75

**证据**

分组键为 NULL（Excel 空单元格，DuckDB GROUP BY 会产出 NULL 组）时，file_tools.py:618-621 的 `{"category": str(row.get("category")), "value": row.get("value")}` 会把 NULL 序列化成字面量字符串 "None" 写进 ChartSpec 与 tool.table，用户看到的柱状图上会出现一根标注 "None" 的柱子、工具回文本也照此展示。另外聚合 SQL 是 `SELECT "group_by" AS category, SUM(CAST(metric AS DOUBLE)) AS value FROM t GROUP BY 1 ORDER BY 1`（file_tools.py:606-608），group_by 不做类型规整，文本型分类（Excel 极常见的「1月…12月」）按字典序排序，x 轴会变成 1月,10月,11月,12月,2月…；折线图顺序会明显失真。现有测试（tests/test_agent_tools.py 的 table_chart 用例）只断言 kind/encode/PNG，未覆盖 NULL 分组与分类顺序。

**建议**

构造 spec 前做分类归一化：①NULL 组——SQL 加 `WHERE "g" IS NOT NULL` 过滤，或显式映射成「(空)」，绝不让 `str(None)` 变 "None"；②顺序——文本分类要么在 SQL 里加数值排序键（如 `ORDER BY TRY_CAST("g" AS DOUBLE) NULLS LAST, "g"`），要么在 §3.5 明写「文本类别按字典序排序」把限制公开。并在 tests/test_agent_tools.py 增加一条用例：用真实 Excel 月份文本构造数据，断言 spec.data.rows 的分类顺序为 1..12 且不出现 "None"（若有空分组则断言被过滤或标注为「(空)」）。

### P2 · PNG 缺失分支的断言恒真，无法证明「降级」发生了

- 位置：`tests/test_agent_tools.py:660-665, 955-959`
- 状态：未闭环
- 置信度：0.75

**证据**

PNG 缺失分支的断言是 `else: assert result.metadata["warnings"]`（tests/test_agent_tools.py:660-665）和 `else: assert step.result.metadata["warnings"]`（tests/test_agent_tools.py:955-959）。但 table_chart 固定 data.time_semantics="none"，chart_render.py:1563 与 :1588 必然追加「time_semantics=none…」「视图时点未知…」两条 warning，所以 warnings 在任何情况下都非空——这两个 else 分支无论「PNG 真的降级了」还是「降级逻辑根本没触发/被写坏」都会通过，等于没有校验降级语义。同类断言在 @pytest.mark.png 用例里用的是 `not any("PNG" in warning …)`（tests/test_agent_tools.py:726），说明仓库已有更强的写法，只是缺失分支没跟上。
