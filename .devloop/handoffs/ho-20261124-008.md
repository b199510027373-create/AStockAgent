### 问题与建议

- P1 · K 线等 export_png=False 的图表被误报为「PNG 降级：kaleido/Chrome 不可用」（open） — 建议：区分「工具未请求 PNG」与「请求了但降级」：在 Figure 上增加 png_requested/png_mode 字段（collect_figures 从 metadata 的 png_mode/export_png 或 png_path 键是否存在推导），export_figures 只在 png_requested 且 png_path 为空时才追加降级说明；figure_embed_html 对未请求 PNG 的图显示「PNG：不适用（该工具不导出 PNG，仅 HTML）」或不显示该行。status 文案改为单层括号，例如「已完成；图表 KLINE…：仅 HTML（该工具不导出 PNG）」。补一条覆盖 export_png=False 工具（K 线）的 UI 断言：status_text 不含「kaleido/Chrome」字样。
- P2 · 空结果分支 metadata 与 §3.5 冻结字段集不一致（缺 citations/png_path/warnings 等）（open） — 建议：二选一并保持唯一口径：①代码对齐契约——空结果同样返回完整字段集（file=file_name、citations=[citation]、title=chart_title、chart_spec=None、artifact_id=""、artifact_version=0、artifact_path=""、png_path=""、data_as_of=""、data_time=""、warnings=["没有可绘制的数据"]）；②文档对齐代码——在 §3.5 明写「空结果分支仅返回 citation/file_id/sheet，其余字段不出现」。无论选哪种，在 tests/test_agent_tools.py 增加一条空结果用例断言实际键集与契约一致（例如断言 set(metadata) 等于冻结集合或等于文档声明的子集）。
- P2 · PNG 缺失分支的断言恒真，无法证明「降级」发生了（open） — 建议：把两个 else 分支改成正向判定降级语义：import chart_render.PNG_DEGRADED_WARNING_PREFIX，断言 `any(w.startswith(PNG_DEGRADED_WARNING_PREFIX) for w in metadata["warnings"])`（或断言任一 warning 同时含「仅 HTML artifact」），并补一条反向断言 `metadata["png_path"] == ""`；png 用例里也把 `"PNG" in warning` 换成同一常量前缀，避免靠字面量偶合通过。
- P2 · 空分组被序列化成字面量「None」，文本分类按字典序排序导致 x 轴顺序失真（open） — 建议：构造 spec 前做分类归一化：①NULL 组——SQL 加 `WHERE "g" IS NOT NULL` 过滤，或显式映射成「(空)」，绝不让 `str(None)` 变 "None"；②顺序——文本分类要么在 SQL 里加数值排序键（如 `ORDER BY TRY_CAST("g" AS DOUBLE) NULLS LAST, "g"`），要么在 §3.5 明写「文本类别按字典序排序」把限制公开。并在 tests/test_agent_tools.py 增加一条用例：用真实 Excel 月份文本构造数据，断言 spec.data.rows 的分类顺序为 1..12 且不出现 "None"（若有空分组则断言被过滤或标注为「(空)」）。
- P2 · 图表导出目录固化在 %TEMP% 且无清理/无注入点，UI 测试往真实临时目录写盘（open） — 建议：①给目录一个注入点：读环境变量（如 `ASTOCK_AGENT_EXPORT_DIR`，缺省仍是 temp 子目录），让测试与部署都能覆盖；②增加保留策略：导出后清掉本目录中超过 N 天或超过 M 个文件的旧产物（或每个 session 一个子目录并在新会话时回收上一个），并在文档里写明位置与清理规则；③测试改为 monkeypatch `agent_chat_ui.AGENT_EXPORT_DIR` 指向 `tmp_path`（或直接对 `export_figures` 传 `tmp_path`），断言文件确实产生在该目录内，避免依赖宿主 %TEMP% 残留。
- P2 · §3.5「title 截断到 120 字符」与实现不一致（只截 chart_spec，metadata.title 未截）（open） — 建议：把描述收敛成单一可验证口径：要么实现侧在 file_tools.py:631 之后统一 `chart_title = chart_title[:120]`，让 spec.title 与 metadata.title 完全一致；要么文档改成「`chart_spec.title` 截断到 120 字符，`metadata.title` 保留用户原始标题」，并在 tests/test_agent_tools.py 加一条超长标题用例把两者关系固定下来（断言 len(spec.title) <= 120 且 metadata.title 与 spec.title 的关系符合文档声明）。
- P1 · AC-2 的下载链路缺运行时证据：launch 与 /file= 从未被启动验证，handoff 自认未走查（open） — 建议：由开发补一次运行时证据，二选一即可：①手工验证——本地 `python app.py` 启动，对一张真实 Excel 让 agent 调 table_chart，打开「图表导出」区分别下载 HTML 与 PNG，确认 HTTP 非 403、PNG 能打开、HTML 内联 plotly 正常渲染，把命令/截图/日志写进 handoff 的 tests 字段；②自动化——新增一条集成用例用 `demo.launch(prevent_thread_lock=True, allowed_paths=[...])` 起本地端口，对导出文件 URL 做 `urllib.request.urlopen` 断言 200 且 `Content-Type` 为 text/html、image/png，然后 `demo.close()`。两种方式任一落地并在 handoff 留证据，本条即可关闭；在此之前 AC-2 视为未完全验证。
