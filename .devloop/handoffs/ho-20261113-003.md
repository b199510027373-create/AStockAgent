### 问题与建议

- P1 · 心跳/验收报表在 15:00–16:40 把当天未到期的 close 任务计为漏跑（open） — 建议：增加 `_due_reference(now)`：当 `(now.hour, now.minute) < _run_time()` 时用 `datetime.combine(now.date(), time(0, 0))` 作为参考时刻再调 last_completed_trade_date（盘前与周末行为不变，只修正 15:00–16:40），并让 heartbeat_check、acceptance_report、_recent_trading_days 内部统一使用该参考值。补两条测试：15:30 且前 4 天 success 时 `--report 5` 仍 all_success=True；15:30 且昨天 failed 时 streak=1、alerted=False、退出码 0。
- P1 · 台账异常会让调度线程静默退出（save_job/_prepare_ledger 在 try 之外）（open） — 建议：把 run_once 中台账读写纳入异常处理（写 running 失败时 `_log` 后返回 None，不向外抛）；在 loop 里用 try/except 包住 startup_maintenance() 与 run_once()，捕获后写入 scheduler.log 并 `stop.wait(600)` 后重试，避免线程终止。补测试：patch `ledger.save_job` 抛 sqlite3.OperationalError，断言 startup_maintenance/run_once 不向调用方抛出，且 loop 在下一轮仍会尝试。
- P2 · 心跳告警去重只在进程内生效，重启后同一签名重复落盘（open） — 建议：把去重签名持久化：写盘前读取 scheduler_alerts.jsonl 最后一行（或维护独立的 name→last_at 表），若与当前 signature 相同且未超过告警间隔则跳过写盘；不在进程内维护可变全局。补一条测试：写行后手动重置 `scheduler._LAST_ALERT_SIGNATURE = None` 模拟重启，再调 heartbeat_check，断言文件仍只有一行。
- P2 · 空台账首次启动即产生 60 日连续漏跑告警（open） — 建议：区分「尚无历史」与「连续漏跑」：若窗口内除当天 pending 行外不存在任何 close 行（last_success 为 None 且无更早 job 记录），返回 ok=True 并带 initialized=False，不写告警、日志注明「尚无调度历史」；streak 以窗口内最早一条 job 的 trade_date 为下界截断。同步调整 test_startup_maintenance_marks_due_job_and_heartbeat_state 的断言，并新增「空库首次启动不告警」用例。
- P2 · 调度执行链 loop() 无测试覆盖（pending→running→success 与失败重试）（open） — 建议：补一条 loop 集成测试：patch `scheduler.datetime` 到某个交易日 16:41、patch `_run_time`/`_is_trading_day`/`run_recommendation`，用一个预先 set 的 threading.Event 让循环在首次 run 后退出，断言 jobs 行由 pending 变 success 且 run_recommendation 只调用一次；再加一条 run_recommendation 返回 stale 的用例，patch `stop.wait` 记录入参，断言调用了 600 且该交易日内没有第二次 run_once。
