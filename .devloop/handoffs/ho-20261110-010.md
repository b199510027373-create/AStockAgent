### 问题与建议

- P1 · 横幅只在页面构建时计算一次，缺少 load 刷新，定时任务产出不会反映到页面（open） — 建议：在 app.py 构建 Blocks 后注册页面加载刷新：让 build_recommend_tab 返回 banner 组件，然后 `app.load(banner_markdown, outputs=banner)`（或在 tab 内用 `banner.load(...)`/`gr.Timer`）；同时补一条结构断言测试（例如断言 Blocks 的 dependencies 中存在 trigger=load 且 outputs 含 banner 的依赖），并在 README 说明「每次打开页面/刷新时重新聚合」。修复人：本分支开发者。完全解决判据：打开页面即拿到最新 ledger 数字，且有测试锁定该 load 绑定。
- P1 · 横幅数据源 tracking 表只由「推荐跟踪」页手工写入，调度任务从不刷新，样本永远为 0（open） — 建议：让每日自动推荐任务结束后同步刷新 T+5 结算（在调度器成功回调里调用 compute_tracking 等价逻辑，或对 tracking 缺失/落后于最新 live run 的天数做增量补算）；若出于网络成本不在调度中补算，则横幅必须显式展示数据截止日（如「跟踪数据截至 2026-10-30，落后 N 个交易日」）并给出触发补算的入口，而不是声称「样本不足」。补测试：存在 live run 但 tracking 落后时，横幅不得断言「样本不足」/或必须显示 stale 文案；以及调度路径确实刷新了 tracking。修复人：本分支开发者。完全解决判据：不手工打开跟踪页，隔日打开推荐页即可看到随样本增长而变化的数字。
- P2 · DB 异常被吞成「样本不足」，use_case 的 error 分支实际不可达（open） — 建议：让 snapshot 把异常转换为独立状态（如 state="error"，携带简短原因），或直接向上抛由 run_alpha_banner 走 failed 分支渲染 ⚠️ 横幅；横幅文案需区分「样本不足（数据正常但没有足够样本）」与「统计读取失败」。补测试：patch tracking_rows 抛 sqlite3.OperationalError 时断言 banner_state=="error"/文案含失败提示而非「样本不足」。修复人：本分支开发者。完全解决判据：DB 故障与样本不足在 UI 上可区分，且测试覆盖该分支。
