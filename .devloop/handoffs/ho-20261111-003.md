### 问题与建议

- P1 · 承接项合并只落在 ADR 正文，工作台数据源 adrs.json 与 contract.json 仍指向已取消的 plan-20261110-004~007（open） — 建议：1) 把 adrs.json 四条 summary 与 contract.json 两条 rationale 的 plan id 改成合并后的 plan-20261107-003/004（ADR-015）、-005（ADR-016）、-008（ADR-017）、-006（ADR-018）；2) 在 tests/test_architecture_gate.py 增加断言：对 adrs.json 的每条 summary 与 contract.json 的每个 rationale 解析 plan-\d{8}-\d{3}，要求 .devloop/plan/items/<id>.json 存在且 status != cancelled，缺失即失败（错误信息列出 id 与引用位置）；3) 补一条手工验证记录：devloop_architecture list 中 015/016/017/018 的 summary 不再出现 20261110。
- P1 · ChatResult 冻结 11 个字段，门禁只校验 10 个名字存在、漏掉 raw，且完全没校验冻结默认值（open） — 建议：把该断言改成与 ToolResult 同级：`assert tuple(gateway.ChatResult.__dataclass_fields__) == ("content","tool_calls","finish_reason","prompt_tokens","completion_tokens","total_tokens","model","provider","protocol","degraded","raw")`；再补默认值断言 `finish_reason == "stop"`、`protocol == "tools"`、`degraded is False`，以及 `total_tokens==0 时等于 prompt+completion` 的行为断言（构造 ChatResult(prompt_tokens=3, completion_tokens=4) 后检查 total_tokens==7）。若 raw 属于平台私有、不打算冻结，则删掉冻结清单里的 raw 并写明理由，二者不能一边冻结一边不设防。
- P1 · 全局禁止 proposed ADR 与 ADR-012「7 天内追认」冲突，会让起草中/待追认的 ADR 必然 CI 红（open） — 建议：二选一并在同一 PR 内使 ADR-012 §5（第 96 行「不存在 proposed ADR」）与门禁一致：a) 门禁只对本次裁决集断言 `set(GATED_ADRS) & proposed == set()`，全局规则改为「proposed ADR 必须带 `- 追认截止：YYYY-MM-DD` 且未过期，否则失败」——既守住「不长期挂着」，又保留 7 天追认窗口；b) 若确实禁止 proposed，则删除 ADR-012 §2 的先行实现条款并写明替代流程（如 ADR 与代码同 PR、评审时置 accepted）。并补一条反例测试：临时造一条 proposed ADR，断言门禁按新规则给出「缺追认截止日」之类可读错误，而不是笼统失败。
- P2 · 落点表 §4 承诺的 test_rule_map_covers_all_contract_rules 不存在，且门禁并不校验本表引用的测试名（open） — 建议：1) 把第 104 行的名字改为实际存在的 `test_rule_map_lists_every_rule_and_review_checklist`，或新增一个真正做这件事的测试再引用它；2) 让门禁真的覆盖本文件：用正则扫描 docs/AStockAgent_contract_rule_map_v1.md 与冻结清单里的 `tests/[\w./-]+\.py::\w+` 引用，逐个用 `_test_functions()` 校验函数存在（不存在且未登记在「缺口与承诺」段则失败）；3) 修好后同步更新 §5 第 3 条的措辞，使承诺与门禁实际能力一致。
