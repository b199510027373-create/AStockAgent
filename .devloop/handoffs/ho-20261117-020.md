### 问题与建议

- P1 · file_list 结果不含引用，收口逻辑会把「有哪些文件」这类合法回答改写成「未在文件中找到」（open） — 建议：把收口范围从「任一文件工具」收窄为「产生了引用定位的工具」：在 runtime.py 新增 `_CITING_FILE_TOOLS = frozenset({"file_search", "file_read", "table_schema", "table_query"})`，`_uses_file_tools` 改用它（file_list 视为清单类工具豁免）；若产品上要求文件清单也必须带出处，则改在 file_tools.py:218-223 给 list_files 补文件级引用（如 metadata["citations"] = [f"《{name}》"]）并在 citations.py 增加 file_level_citation，二者选一。同时在 tests/test_agent_runtime.py::FileCitationTests 增加一例：FakeModel 先 `ToolCall("file_list", {})` 再回答「共 2 个文件：《年报.pdf》、《财务.xlsx》」，断言 `run.answer` 原样保留而不是「未在文件中找到」。
- P1 · 引用白名单从工具正文抽取，文档正文（不可信数据）可注入「《X》第 N 页」绕过防编造校验（open） — 建议：白名单只取结构化字段：runtime.py:94-102 的 `metadata["citations"]`、`metadata["citation"]` 与 table 行 `citation` 已经覆盖 file_search/file_read/table_schema/table_query 的全部合法定位，删掉 runtime.py:103-104 对 `result.text` 的 `extract_citations` 抽取（正文不再参与白名单构建）；如果确实需要从 text 兜底，只对工具自己生成的行首引用行提取（如 `result.text.splitlines()[:1]`），不要对整个正文做匹配。补一条运行时测试：file_read 返回的正文里包含「《虚构.pdf》第 9 页」，模型回答引用该串，断言最终答案是「引用：《真实文件》…」重建结果，而不是保留模型正文。
- P2 · FILE_CHUNKS_TRIGGER_DDL 被两次赋值，遗留的旧 ai/ad/au 触发器脚本与新 contentless 表结构冲突（open） — 建议：删除 files.py:186-202 中重复赋值的旧触发器脚本，只保留一行说明 `FILE_CHUNKS_TRIGGER_DDL = ""  # 新布局由 Python 写 tokens，不再使用触发器`；如果该常量已无外部调用，同时从 `__all__`（files.py:55）移除，或改为在 tests/test_agent_tools.py 增加断言 `F.FILE_CHUNKS_TRIGGER_DDL == ""` 钉住「不再使用触发器」这个契约，避免以后有人把它当真执行。
