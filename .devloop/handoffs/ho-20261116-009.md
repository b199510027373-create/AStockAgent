### 问题与建议

- P1 · 主 test job 也被绑到真实 PNG 导出：无 per-test timeout，Chrome/kaleido 抖动会拖红整个主流水线（open） — 建议：把真实导出彻底隔离到一个 job：1) 给两个 PNG 模块加 `pytestmark = pytest.mark.png`（或在 pytest.ini/pyproject 注册 marker）；2) 主 job 改成 `coverage run -m pytest tests -q -m "not png"`（或 `--deselect tests/test_agent_chart_png_export.py --deselect tests/test_agent_chart_png_zh.py`），并删掉主 job 的 fonts-noto-cjk 安装步骤（省 ~30s，字体只在 png-export 需要）；3) png-export job 用 `-m png --timeout=180` 保持现状。改完在 PR 贴一次新的 CI run：test job 不再依赖 Chrome、png-export 仍绿；同步更新 docs/AStockAgent_png_export_ops.md:117-118 的「主 job 也真实执行」表述。
- P2 · require 失败时「run 记 failed」只对新建 run 生效：已有 run_id 因 ON CONFLICT DO NOTHING 不会被改成 failed（open） — 建议：require 失败分支在 ensure_run 之后显式落状态，例如新增 `store.fail_run(conn, run_key, reason=...)`（`UPDATE agent_runs SET status='failed', finished_at=? WHERE run_id=?`），或给 ensure_run 增加 `force_status: bool = False` 参数；补一条测试：先 `ensure_run(conn, "run_require", status="running")` 预建 run，再触发 require 失败，断言 status 变为 failed 且 artifact 行仍为 0。若产品上不希望把预建 run 置 failed，则改 ops 文档与 docstring，不要宣称「run 记 failed」。
- P2 · 复用旧 PNG 时 meta 留下矛盾的 provenance：degraded=False + 旧 png_path，却保留本次的 png_mode/png_error（open） — 建议：复用旧 PNG 时显式标注来源：在 _merge_artifact_meta 里加 `merged["png_reused"] = True`，并把 `png_error` 改名/迁移为 `png_last_attempt_error`（或直接置 None，把原因保留在一个不会与 degraded=False 冲突的键里）；同时把「产出该 PNG 的模式」写成 `png_source_mode`，不要用本次的 `png_mode` 冒充。补一条 store 级测试：先成功 PNG、再以 degraded/off 重写同一 artifact_id，断言 `png_reused=True`、`degraded=False`、`png_error` 不再表示「当前无 PNG」，且 `png_mode` 不误导。
