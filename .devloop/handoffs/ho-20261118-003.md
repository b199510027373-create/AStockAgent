### 问题与建议

- P1 · artifact 身份未包含 include_plotlyjs，同一 spec/data/env 切换内联/CDN 会撞身份并硬失败（open） — 建议：把会影响 HTML 字节的渲染选项纳入身份：在 canonical_spec 中加入 render_options.include_plotlyjs（以及未来任何输出影响参数），或把 HTML content_digest 一并纳入 artifact_id 种子；record_artifact 的 content_digest 校验应只用于同一身份的内容一致性。补回归测试：同一 spec/data/env 下 include_plotlyjs="inline" 与 "cdn" 各渲染一次，断言生成两个 artifact（或明确后者复用前者的策略），且不抛 ArtifactIdentityConflict；再断言两次的 HTML 均可读。
- P2 · 内存库 v1 迁移仍把 DEFAULT_DB_PATH 当备份目标（P2-G 仅部分修复）（open） — 建议：把“内存库/不需要备份”与“未提供路径”区分开：可让 migrate_v1_to_v2 接受 `db_path=None` 表示不备份（内存库直接跳过），另设显式默认参数或由 connect 传入真实路径；或在 _backup_database 开头检查 `conn.execute("PRAGMA database_list")` 的 main file 为空时直接 return None，不要回退 DEFAULT_DB_PATH。补测试：`:memory:` 上建 v1 三表后调 ensure_schema，断言迁移成功且没有在 DEFAULT_DB_PATH 旁产生 .bak 文件。
- P1 · GC 的 protected 集合漏掉 data_blob，90 天后会删掉仍被 artifact 引用的数据快照（open） — 建议：在 _protected_paths 的 meta 遍历中加入 data_blob（同样做相对路径规范化与 is_relative_to 校验），并让 prune_artifacts/prune_orphan_blobs 都使用它；补回归测试：真实 render 生成 data.json 后，把 mtime 改到 90 天前，调用 prune_artifacts/prune_orphan_blobs，断言 data.json 仍在且 load_artifact(recomputed) 仍可回放；同时断言无引用的 blob 仍会被删。另建议把 data_blob 与 png_rel_path 的键名统一成白名单常量，避免以后新增 blob 再漏。
