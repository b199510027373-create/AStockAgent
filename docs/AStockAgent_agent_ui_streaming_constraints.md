# Agent 会话 UI 流式输出边界（v1）

状态：设计约束，2026-11-19。适用于 `astock/agent/chat.py` 与 `astock/agent_chat_ui.py`。

## 1. 队列阻塞是设计选择，不是缺陷

控制器用有界 `queue.Queue` 把 Agent 线程的事件交给 Gradio 生成器。消费者在空队列上阻塞，等生产者放入下一帧或结束哨兵；这样：

- 同一时刻只有一条回答在流式输出，不需要轮询；
- 队列有界，生产端不会无限占用内存；
- 正常生产端一定会放结束哨兵，阻塞时间由模型/工具调用时长决定。

已接受的限制：如果模型适配器永远不返回、也不放哨兵，消费者会一直等。生产环境由模型 HTTP read timeout、工具超时和运行时 `timeout_seconds` 兜底；测试里的 `FakeModel` 才可能无限阻塞。UI 不额外加“队列看门狗”，避免把正常的慢首字误判为卡死。

## 2. 停止输出与中断是两条路径

- **生成中**：`ChatEvent(kind="answer")` 分片写入；点“停止输出”设置 `_stop_output`，已产出的分片保留，后续 `done` 不得用完整 `result.answer` 覆盖。
- **运行中**：控制器先检查 `_running`，再调用 `runtime.request_interrupt_if_running()`；该方法在运行时锁内同时检查“是否在途”并设置中断，消除检查与设置之间的 TOCTOU 窗口。
- **预运行中断**：`runtime.request_interrupt()` 仍保留“下一轮开始前先埋中断”的语义，供测试/批处理使用；UI 不再用它转发在途中断。
- 若 run 恰好在 UI 检查后结束，`request_interrupt_if_running()` 返回 `False`，不留下中断标记；控制器转入输出阶段停止分支，只停止本轮流式输出。

## 3. 失败与降级

- 模型未就绪：显示“模型未就绪”，仍允许上传文件；提问返回降级提示。
- 队列生产端异常：必须放结束哨兵，并在 `done` 中带 `error`；消费者不得永久等待。
- 无 API key 的真实模型 E2E 不进入普通 CI；由 `plan-20261119-002` 在显式配置下运行。
